# Проблемные места
- Сложно построить отчеты за разумное время. За счет этого растет time-to-market
- Сложность масштабирования данных
- Отсутствие разграничения доступа к данным в зависимости от уровня доступа
- Отсутствие возможности составить отчет самостоятельно. Для получения отчет нужно обращаться к команде DWH
которая может быть сильно загружена
- Сложность развивать направления независимо (финансы компании, медицина, банки, персонал, инвентаризации и пр.),
- Не могут увидеть единую картину по бизнес показателям
- Текущая DWH работает на базе Microsoft SQL-сервера 2008 года технологически устарела и снят с поддержки. Его уровень
безопасности, возможности интеграции, возможности поддержки разных форматов и производительность уступает современным решениям
- Старая интеграционная шина (Apache Camel) с низкой производительностью

Приоритеты
1. Must (обязательно)
- Сложно построить отчеты за разумное время. За счет этого растет time-to-market
2. Should (нужно)
- Сложность масштабирования данных
- Отсутствие возможности конструировать отчеты самостоятельно
- Сложность развивать направления независимо
3. Could (желательно)
- Отсутствие разграничения доступа к данным в зависимости от уровня доступа
4. Won’t Have this time (можно перенести)
- Мигрировать из Microsoft SQL-сервера 2008 на ClickHause 
- Миграция интеграционная шины с Apache Camel на Kafka
